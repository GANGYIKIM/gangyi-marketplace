# 맥락 없는 독자 검증

초안을 저장하기 전에, 대화를 보지 못한 독자가 이 문서만으로 아이디어를 이해할 수 있는지 확인한다. 작성자는 대화 맥락을 알고 있어서 빈틈을 스스로 발견하기 어렵기 때문이다.

사용자에게 "저장 전에 맥락 없는 독자가 먼저 읽어볼게요. 질문이 나오면 한 번에 여쭐게요"라고 알린다.

## 서브에이전트가 있는 환경

새 서브에이전트에게 초안 전체와 아래 지시만 전달한다. 대화 내용은 넘기지 않는다.

```
다음은 어떤 아이디어를 정리한 문서다. 너는 이 아이디어를 처음 접하는 사람이다.
이 문서는 완성된 글이나 기획서가 아니라 방향을 잡는 아이디어 노트다.
세부 정보가 없는 것보다 방향이 이해되지 않는 것을 찾는 데 집중하라.
문서만 읽고 답하라.

1. 이 아이디어를 세 문장으로 요약하라.
2. 이해되지 않거나 모호한 부분을 모두 질문으로 적어라.
3. 이 문서를 바탕으로 다음 행동(조사, 기획, 작성 등)을 하려 할 때, 작성자에게 꼭 물어야 할 것을 적어라.

[초안]
```

## 서브에이전트가 없는 환경

Claude가 대화 내용을 모르는 독자라고 가정하고 초안만 다시 읽으며 위 세 가지에 직접 답한다. 대화에서 들은 내용으로 빈틈을 메우지 않도록 주의한다.

## 결과 분류

나온 질문을 세 갈래로 나눈다.

| 분류 | 기준 | 처리 |
|---|---|---|
| 이미 답이 있음 | 대화에 답이 있었지만 문서에 빠짐 | 문서에 반영한다 |
| 사소함 | 누가 정해도 아이디어의 본질이 바뀌지 않음 | Claude가 정하고 문서에 `(Claude 판단)`으로 표시한다 |
| 완성물에서 정할 세부 | 날짜, 이름, 수치처럼 실제 글이나 결과물을 만들 때 필요하고 방향에는 영향이 없음 | 사용자에게 묻지 않는다. 필요하면 열린 질문에 짧게 남기고, 아니면 버린다 |
| 사용자 몫 | 사용자만 답할 수 있고, 답에 따라 내용이 달라짐 | 한 메시지에 모아 중요한 것부터 묻는다 |

요약이 사용자의 의도와 다르면, 그 차이가 생긴 섹션을 먼저 고친다. 검증으로 생기는 질문 묶음은 한 번만 묻는다.
