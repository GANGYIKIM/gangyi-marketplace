# 아이디어 문서 템플릿

## 목차

1. 작성 원칙
2. 기본 뼈대
3. 성격별 추가 섹션
4. CHANGELOG 형식

## 1. 작성 원칙

사람이 훑어 읽어도, AI가 맥락 없이 읽어도 이해되게 쓴다.

- 각 섹션의 첫 문장에 그 섹션의 요점을 쓴다. 나머지 문장은 요점을 뒷받침한다.
- 섹션은 짧게 유지하고, 길어지면 `###` 하위 섹션으로 나눈다. 헤더는 `###`까지만 쓴다.
- 대화에서만 통하는 말("아까 말한 그거")을 쓰지 않는다. 처음 나오는 용어는 한 번 풀어 쓴다.
- 사용자가 정한 것과 Claude가 판단한 것을 구분한다. Claude의 판단에는 `(Claude 판단)`을 붙인다.
- 비어 있는 섹션은 지운다. 열린 질문이 없으면 "열린 질문" 섹션도 생략한다.

## 2. 기본 뼈대

모든 아이디어 문서에 들어간다.

```markdown
# [아이디어 제목]

> [한 줄 요약: 이 문서를 처음 보는 사람이 이것만 읽어도 무엇에 관한 생각인지 알 수 있게]

- 작성일: YYYY-MM-DD
- 버전: v1

## 목차

## 1. 배경
이 생각이 어디서, 어떤 계기로 시작됐는지

## 2. 핵심 내용
아이디어 자체. 필요하면 ### 하위 섹션으로 나눈다

## [성격별 추가 섹션들]

## N. 열린 질문
아직 정리되지 않았거나 더 알아봐야 할 것
```

v2부터는 버전 줄을 `- 버전: v2 (변경 이력: CHANGELOG.md)`처럼 쓴다. 작성일은 처음 쓴 날짜를 유지하고, 수정 날짜는 CHANGELOG에만 적는다.

## 3. 성격별 추가 섹션

아이디어의 성격에 맞는 것을 제안하고, 사용자가 고른 것만 넣는다. 아래에 없는 섹션이 더 맞으면 새로 제안해도 된다. "핵심 내용"과 "열린 질문" 사이에 둔다.

| 성격 | 섹션 | 담을 내용 |
|---|---|---|
| 프로젝트 | 목표 | 이루고 싶은 것, 이번에 하지 않을 것(비목표), 동작해도 실패로 볼 상황 |
| 프로젝트 | 제약 조건 | 기술, 시간, 비용, 환경 |
| 프로젝트 | 결정된 사항 | 사용자가 정한 것과 Claude가 정한 것을 구분 |
| 개념·공부 | 관련 자료 | 참고한 글, 링크, 책 |
| 개념·공부 | 연결 | 이미 알던 다른 개념과의 관계 |
| 고민 | 선택지 | 고려 중인 방향들 |
| 고민 | 판단 기준 | 무엇을 기준으로 고를지 |
| 글감 | 독자와 메시지 | 누구에게, 무엇을 전하려는지 |
| 글감 | 글의 재료 | 글에 넣고 싶은 사례, 경험, 예시, 자료. "핵심 내용"이 말하고 싶은 것이라면, 이 섹션은 그걸 보여줄 근거와 소재다 |

## 4. CHANGELOG 형식

`ideas/<slug>/CHANGELOG.md`에 둔다. 첫 새 버전(v2)을 만들 때 생성하고, 이후에는 새 항목을 맨 위에 더하기만 한다. 기존 항목은 고치지 않는다.

```markdown
# 변경 이력: [아이디어 제목]

## v2 (YYYY-MM-DD)
- 파일: `<slug>-v2.md`
- [이전 버전과 달라진 점을 한 줄씩]

## v1 (YYYY-MM-DD)
- 파일: `<slug>.md`
- 처음 작성
```
