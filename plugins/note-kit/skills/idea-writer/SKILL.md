# Idea Writer

사람은 아이디어를 말할 때 대부분 아직 생각을 끝내지 못한 상태다. 이 스킬의 목적은 좋은 질문으로 사용자가 스스로 생각을 끝까지 밀고 가게 돕고, 그 결과를 나중에 다른 사람이나 AI가 대화 맥락 없이 읽어도 이해할 수 있는 문서로 남기는 것이다.

## 핵심 원칙

대화 내내 지킨다. 컴팩션 뒤에도 이 섹션만큼은 다시 확인한다.

- **질문은 메시지마다 하나만 하고, 종류에 따라 형태를 다르게 한다.**
  - **생각을 묻는 질문**(배경, 핵심 내용, 목표처럼 아이디어 자체를 묻는 것)에는 보기 목록을 달지 않는다. 보기는 사용자의 생각을 Claude가 떠올린 방향으로 끌고 가서 아이디어를 제한한다. 사용자가 막히거나 "추천해줘", "네 생각은?"이라고 할 때만 구체적인 제안을 한다.
  - **진행을 정하는 질문**(넣을 섹션 고르기, 다음 단계 선택, 저장 여부처럼 작업 방식을 정하는 것)에는 보기 목록을 보여준다. 아이디어의 내용이 아니라 형식과 절차를 고르는 것이라, 선택지를 보여주는 편이 빠르고 정확하다.
- **추측은 추측으로 표시한다.** Claude가 짐작한 내용은 `*추측:*`을 붙인다. 사용자가 직접 말한 것만 사용자의 생각으로 적는다. 고칠 수 있는 추측("혹시 X 때문에 불편했던 건가요?")은 열린 질문보다 대화를 빠르게 진전시킬 때가 많다.
- **추측은 그 추측에 대한 명시적인 답이 있을 때만 확정한다.** 다른 질문에 대한 "좋아"나 침묵은 추측을 확정하지 않는다. 확인받지 못한 추측은 `*추측:*` 표시를 유지한 채 다음 되짚기나 독자 검증에서 다시 확인한다.
- **승인 전에는 파일을 만들지 않는다.** 되짚기에 대한 "좋아"는 그 부분에 대한 동의일 뿐, 아직 보여주지 않은 문서 전체에 대한 승인이 아니다.
- **문서와 대화는 한국어로 쓴다.** 사용자의 말투와 어휘에 맞추고, 절차 용어("1단계 진입" 같은 말)는 쓰지 않는다.

## 진행 순서

진행하면서 아래 체크리스트를 따른다.

- [ ] 1. 시작 판단
- [ ] 2. 대화로 구체화 (질문과 되짚기를 번갈아)
- [ ] 3. 섹션 제안
- [ ] 4. 초안 작성과 독자 검증
- [ ] 5. 남은 질문을 한 번에 확인
- [ ] 6. 승인 후 저장

### 1. 시작 판단

- 기존 문서를 업데이트하는 요청이면 해당 폴더의 **최신 버전**을 먼저 읽는다.
- 사용자가 참고 자료나 파일, 링크를 가리키면 질문하기 전에 먼저 읽는다. 이미 적혀 있는 내용을 다시 묻지 않기 위해서다.
- 요청에 필요한 내용이 이미 다 있으면 대화를 길게 끌지 않는다. 바로 초안으로 간다.
- 그렇지 않으면 첫 메시지를 다음 두 가지로만 구성한다.
  1. "질문 없이 바로 정리하길 원하면 말해주세요"라는 안내 한 줄
  2. 사용자가 묘사하게 만드는 열린 질문 하나. 추상적인 질문보다 구체적인 장면을 묻는다. 예: "이 생각이 처음 든 순간이 언제였어요?"

사용자가 질문을 건너뛰겠다고 하면 지금까지의 내용으로 4단계 초안부터 시작한다.

### 2. 대화로 구체화

아래는 다룰 영역이지 질문 목록이 아니다. 그대로 읽어주지 않는다.

- 이 생각이 무엇이고, 어디서 시작됐는지
- 왜 지금 중요한지, 정리되면 무엇이 좋아지는지
- 이미 본 것, 시도한 것, 좋았거나 싫었던 사례
- 사용자가 특히 신경 쓰는 디테일
- 아직 모르는 것

**되짚기:** 한 부분을 설명할 수 있을 만큼 이해하면 그 부분을 200~300단어로 정리해 보여준다. 추측은 `*추측:*`으로 표시하고, 마지막에 "틀리거나 빠진 게 있나요?"로 묻는다. 확인을 받으면 다음 부분 질문으로 넘어간다. 질문과 되짚기를 대화 끝까지 번갈아 한다.

**답 대신 다른 말이 돌아올 때:** 사용자가 질문에 답하지 않고 다른 내용을 덧붙이면, 그 내용을 먼저 짧게 반영하고 같은 질문을 다시 한다. 새 내용이 질문을 무의미하게 만들었다면 그 질문은 버린다.

**정리할 재료가 없을 때:** 이 스킬은 사용자 안에 이미 있는 생각을 끌어내 정리하는 도구다. 각도를 바꿔 물어도 "없어", "모르겠어"가 이어지고, 사용자가 원하는 것이 정리보다 조언("나한테 맞는 방향을 알려줘")에 가깝다는 게 보이면 같은 방식의 질문을 계속하지 않는다. 지금은 정리할 생각보다 조언이 먼저 필요해 보인다고 솔직하게 말하고, 진행을 정하는 질문으로 다음 중 하나를 고르게 한다.
- 지금까지 나온 내용을 배경과 열린 질문 위주의 짧은 문서로 남긴다
- 정리를 멈추고 조언부터 받는다

**생각은 넓게, 제안은 좁게:** 무언가를 제안하기 전에 여러 방향을 속으로 떠올리고, 사용자가 말한 이유와 어긋나는 것은 버린다. 비교가 결정에 도움이 될 때만 비교를 보여준다.

### 3. 섹션 제안

아이디어의 성격이 보이면, 기본 뼈대에 더할 섹션을 [references/template.md](references/template.md)에서 골라 제안하고 사용자가 고르게 한다. 프로젝트가 아닌 생각에 목표·제약 같은 실행용 섹션을 억지로 넣지 않는다.

### 4. 초안 작성과 독자 검증

[references/template.md](references/template.md)의 구조로 초안을 쓴 뒤, 파일로 저장하기 전에 [references/reader-check.md](references/reader-check.md)의 절차로 맥락 없는 독자 검증을 한다.

### 5. 남은 질문 확인

독자 검증에서 사용자만 답할 수 있는 질문이 나오면 **한 메시지에 모아서** 중요한 것부터 묻는다. 이 단계만 예외적으로 여러 질문을 한 번에 한다. 답을 반영한 뒤, Claude가 스스로 판단한 부분의 짧은 목록과 함께 초안 전체를 보여준다.

### 6. 승인 후 저장

사용자가 초안을 승인하면 아래 저장 규칙대로 저장한다. 저장 위치를 물어야 하는 경우(저장 규칙의 "저장 위치" 4번)에는 초안 승인을 묻는 질문에 위치 질문을 함께 넣어 한 번에 묻는다.

## 저장 규칙

- **제목:** 20자 안팎의 명확한 명사구로 제안하고 사용자에게 확인받는다. 구어체 문장은 피한다. 제목이 곧 폴더와 파일 이름이 되므로, 나중에 목록에서 봐도 무엇에 관한 문서인지 알 수 있어야 한다. 예: "LLM Wiki로 만드는 개인 공부 위키"(구어체) → "LLM-Wiki 기반 개인 위키"
- **저장 위치:** 아래에서 처음 해당하는 것을 따른다.
  1. 사용자가 이번 요청에서 위치를 말했으면 그곳
  2. 프로젝트의 CLAUDE.md에 아이디어 저장 위치 규칙이 있으면 그곳
  3. `ideas/` 폴더가 이미 있으면 그곳
  4. 위에 모두 해당하지 않으면 처음 만드는 것이다. "기본 위치인 `ideas/`에 만들까요, 다른 위치를 지정하실래요?"라고 묻는다. 사용자가 `ideas/`가 아닌 위치를 고르면, 다음에 같은 질문을 받지 않도록 "이 위치를 CLAUDE.md에 규칙으로 남길까요?"라고 한 번 더 묻는다.
- **경로:** 저장 위치가 어디든 아이디어마다 하위 폴더를 만들어 `<저장 위치>/<slug>/<slug>.md`에 저장한다. 예: `ideas/llm-wiki-기반-개인-위키/llm-wiki-기반-개인-위키.md`, `아이디어/llm-wiki-기반-개인-위키/llm-wiki-기반-개인-위키.md`
- **slug:** 아이디어 제목에서 공백은 하이픈으로 바꾸고, 영문은 소문자로, 파일 이름에 쓸 수 없는 문자(`/ \ : * ? " < > |`)는 지운다. 한글은 그대로 둔다. 예: "LLM Wiki 구축" → `llm-wiki-구축`
- **버저닝:** 같은 이름의 문서가 폴더에 있으면 절대 덮어쓰지 않는다. 폴더 안의 `<slug>.md`, `<slug>-v2.md` … 중 가장 큰 번호를 찾아 다음 번호로 새 파일을 만든다. 번호 없는 원본은 v1로 본다.
- **변경 이력:** 이력은 문서 안이 아니라 같은 폴더의 `CHANGELOG.md`에 남긴다. 버전 문서마다 이력이 중복되지 않고, 아이디어 문서에는 내용만 남게 하기 위해서다. 첫 새 버전(v2)을 만들 때 `CHANGELOG.md`를 만들고, 이후에는 기존 내용을 고치지 않고 새 버전 항목을 더하기만 한다. 새 버전 문서의 버전 줄에는 CHANGELOG 안내를 붙인다. 형식은 template.md를 따른다.
- **파일 시스템이 없는 환경:** 같은 이름 규칙으로 다운로드할 수 있는 파일을 만들어 건넨다.
