# 요약 문서 형식

## 기본 구조

```markdown
# [원본 제목]

- 원본 파일: `clips/react19_출시.html`
- 원문 주소: https://example.com/...
- 요약일: YYYY-MM-DD
- 작성: AI 요약 (원문과 다를 수 있음)

> [한 줄 요약]

## 핵심 내용
- [원문이 말하는 것만, 새로 풀어 쓴 문장으로]

## AI 해석
- [원문에 직접 적혀 있지 않은 추론, 배경 설명, 다른 개념과의 연결]
```

- **원본 제목:** 원본에 제목이 있으면 그 제목을 한국어로 옮긴다. 없으면 파일 이름을 쓴다.
- **원본 파일:** 원본 파일의 경로. 대화에 붙여 넣은 글이면 `(대화에 붙여 넣은 글)`로 적는다. 같은 이름의 요약이 있을 때 같은 원본인지 판단하는 기준이므로 빠뜨리지 않는다.
- **원문 주소:** 원문이 웹에 있을 때만 적는다. 찾지 못하면 이 줄을 지운다.
- **AI 해석:** 덧붙일 해석이 없으면 섹션째 지운다. 빈 섹션을 남기지 않는다.

## 원문 주소 찾기

원본 파일 안에서 다음 순서로 찾고, 처음 찾은 주소를 쓴다.

1. 마크다운 프론트매터의 `source`, `url`, `원문 주소` 같은 필드
2. HTML의 `<link rel="canonical">` 또는 `<meta property="og:url">`
3. 본문 맨 위나 맨 아래에 "원문", "출처", "Source"로 표시된 주소

본문 중간에 나오는 참고 링크는 원문 주소가 아니다. 사용자가 요청에서 주소를 직접 알려 줬으면 그것을 쓴다.

## 형식별 읽기

| 원본 형식 | 읽는 방법 |
|---|---|
| md, txt | 그대로 읽는다 |
| HTML | 본문만 요약한다. 메뉴, 광고, 푸터, 댓글처럼 본문이 아닌 텍스트는 무시한다 |
| PDF | 10쪽이 넘으면 한 번에 읽지 말고 쪽 범위를 나눠 읽는다. 큰 PDF를 쪽 범위 없이 읽으면 읽기가 실패한다 |
| 이미지 (png, jpg 등) | 이미지에 담긴 글이나 정보를 요약한다. 글이나 정보가 거의 없는 사진이면 요약 대신 무엇이 보이는지 설명하고, 한 줄 요약 앞에 "이미지 설명:"을 붙여 요약이 아님을 밝힌다 |
| docx, pptx, 영상 등 | 읽을 수 없으므로 요약하지 않는다. SKILL.md 1단계대로 알리고 멈춘다 |

## 길이

원문을 다시 읽지 않아도 무엇을 말하는지 알 수 있는 정도까지만 쓰고, 원문을 대신할 만큼 길게 쓰지 않는다.

- **짧은 글:** 핵심 내용 5개 이하. 원문에 있는 만큼만 쓰고, 항목 수를 채우려고 내용을 만들지 않는다.
- **긴 글이나 여러 주제를 다루는 글:** 원문의 큰 흐름에 맞춰 `###` 하위 섹션으로 나누고, 섹션마다 2~4개 항목

## 예시

입력: 원본 파일 `clips/react19_출시.md` (영어 글, 프론트매터에 `source: https://example.com/react-19`)

출력: `summaries/react19_출시.md`

```markdown
# React 19 출시

- 원본 파일: `clips/react19_출시.md`
- 원문 주소: https://example.com/react-19
- 요약일: 2026-10-15
- 작성: AI 요약 (원문과 다를 수 있음)

> React 19가 정식 출시되며 비동기 상태 처리와 서버 렌더링 기능이 기본으로 들어왔다.

## 핵심 내용
- 폼 제출 같은 비동기 작업의 대기·오류 상태를 다루는 액션(Actions)이 추가됐다.
- 서버 컴포넌트(Server Components)가 실험 단계를 벗어나 안정 기능이 됐다.
- 업그레이드할 때 일부 오래된 API가 제거되므로 마이그레이션 가이드를 먼저 확인하라고 안내한다.

## AI 해석
- 액션은 기존에 상태 관리 라이브러리로 처리하던 폼 상태 일부를 React 자체로 옮길 수 있게 해 준다.
```
