# 실패 사유 분류

`clipper.py fetch`가 실패하면 출력의 `reason`에 아래 형식의 사유가 들어 있다. 이 문자열을 그대로 clip-log에 기록한다.

```
<분류>: <상세 사유> (재시도 가능|재시도 불가)
예: 접근 제한: 로그인 필요 (401) (재시도 불가)
```

## 분류표

| 분류 | 상세 사유 예시 | 재시도 |
|---|---|---|
| 주소 오류 | 잘못된 형식의 주소, 존재하지 않는 도메인 | 불가 |
| 페이지 없음 | 404, 410 | 불가 |
| 접근 제한 | 로그인 필요, 로그인 페이지로 이동함, 권한 없음 또는 봇 차단(403), 유료 구독 | 불가 |
| 서버 오류 | 500, 502, 503, 요청 과다(429) | 가능 |
| 네트워크 | 시간 초과, 연결 실패 | 가능 |
| 본문 없음 | 본문을 거의 뽑지 못함 | 가능 |
| 도구 오류 | 브라우저 실행 실패, Chrome 실행 실패, 캡처 실패, 패키지 미설치 | 가능 |

## 403과 봇 차단

차단 표시가 없는 403도 화면 없는 브라우저만 막는 경우가 많아서 "권한 없음 또는 봇 차단"으로 적는다. 이때 스크립트는 설치된 Chrome 창으로 한 번 더 시도하고, 그래도 막히면 원래 사유를 그대로 남긴다. 이 실패는 다시 시도해도 같아서 "재시도 불가"지만, 브라우저에서 저장한 HTML 파일로는 클리핑할 수 있으므로 그 방법을 안내한다.

## 스크립트가 잡지 못하는 경우

스크립트는 상태 코드, 로그인 화면, 본문 길이로 판단한다. 유료 구독 안내처럼 페이지는 정상으로 열리지만 본문이 막힌 경우는 놓칠 수 있다. 그래서 fetch가 성공해도 출력의 `text_preview`를 읽고, 본문 대신 구독·로그인 안내만 보이면 저장하지 않고 직접 실패로 기록한다.

```
접근 제한: 유료 구독 (재시도 불가)
```

이때는 `fetch`가 만든 임시 폴더를 지운다.

## 표에 없는 실패

표의 분류 중 가장 가까운 것을 고르고, 상세 사유는 짧게 새로 쓴다. 다시 시도했을 때 결과가 달라질 수 있으면 "재시도 가능", 아니면 "재시도 불가"로 적는다.
