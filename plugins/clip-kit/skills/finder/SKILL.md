# Finder

저장한 클립을 찾는다. 클립 본문은 Claude가 직접 읽지 않고 스크립트가 훑어서 결과만 넘긴다. 클립이 많아져도 토큰을 쓰지 않기 위해서다.

## 원칙

- **읽기만 한다.** 클립, 기록, 요약 파일을 바꾸거나 지우지 않는다.
- **클립 수와 상관없이 항상 `finder.py`로 찾는다.** 클립이 몇 개뿐이어도 HTML을 Read나 `cat`으로 열어 훑지 않는다. 지금 몇 개를 직접 읽는 습관이 클립이 쌓였을 때 큰 비용이 된다.
- **검색어는 넓혀서 넘긴다.** 스크립트는 글자 그대로만 찾으므로, 내용 검색이면 사용자의 표현에 더해 같은 뜻의 다른 표현, 영어 표현, 흔한 약어를 3~6개 함께 넘긴다. 예: "서버 컴포넌트" → `서버 컴포넌트`, `Server Components`, `RSC`

## 스크립트

`${CLAUDE_SKILL_DIR}/scripts/finder.py`를 실행한다(이하 `finder`). 결과는 JSON 한 줄이다.

| 명령 | 하는 일 |
|---|---|
| `finder search --root ROOT [조건...]` | 클립 찾기. 조건: `--since`, `--until`(YYYY-MM-DD), `--site`, `--keyword`(여러 번), `--summaries`, `--no-summary` |
| `finder failures --root ROOT [--include-excluded]` | 실패한 링크 목록 |

## 진행 순서

### 1. 위치 정하기

- **클립 위치(ROOT):** 이번 요청에서 말한 위치 → 프로젝트 CLAUDE.md의 클립 저장 위치 규칙 → `clips/` 순서로 처음 해당하는 것
- **요약 위치:** 이번 요청에서 말한 위치 → CLAUDE.md의 요약 저장 위치 규칙 → `summaries/` 순서로 처음 해당하는 것. 있으면 `--summaries`로 넘긴다.

ROOT가 없으면 "저장된 클립이 없어요"라고 알리고 끝낸다.

### 2. 조건 정하기

- **날짜:** "지난주", "어제" 같은 말은 오늘 날짜를 기준으로 `--since`, `--until`로 바꾼다.
- **사이트:** "원티드" 같은 이름은 도메인 일부(`wanted`)로 바꿔 `--site`에 넘긴다.
- **내용:** 원칙대로 검색어를 넓혀 `--keyword`를 여러 번 넘긴다.
- **요약 여부:** "요약 안 된 클립"이면 `--no-summary`를 붙인다.
- **실패한 링크:** "실패한 링크 보여줘"면 `finder failures`를 쓴다. "제외한 것까지"면 `--include-excluded`를 붙인다.

### 3. 결과 알리기

결과를 표로 보여준다: 클립 제목, 저장일, 사이트, 맞은 검색어. 결과를 설명하려고 클립 HTML을 열어 본문을 인용하지 않는다. 내용이 궁금하면 요약 경로를 안내하고, 사용자가 원할 때만 파일을 열어 준다. 각 클립에 대해 요약이 있으면 "요약으로 확인할 수 있어요 (`<요약 경로>`)", 없으면 "요약 없음"이라고 적는다.

- `truncated`가 true면 상위 결과만 보여준 것이라고 알리고, 조건을 좁히자고 제안한다.
- 결과가 없으면 조건을 한 번 넓혀 다시 찾고(검색어 추가, 날짜 범위 확대), 그래도 없으면 없다고 알린다.
- 실패한 링크 목록을 보여준 뒤에는 "다시 시도하거나 정리하려면 말씀해 주세요"라고만 덧붙인다. 직접 재시도하지 않는다.

사용자가 원하면 클립의 HTML이나 캡처를 연다(macOS에서는 `open <경로>`).
