# Retry Clipper

클리핑에 실패한 링크를 관리한다. 무엇을 다시 할지 정리하고 고르게 하는 것까지가 이 스킬의 일이고, 실제 클리핑은 link-clipper가 맡는다. 클리핑 과정을 두 곳에 두지 않기 위해서다.

## 원칙

- **직접 클리핑하지 않는다.** 다시 시도할 링크는 link-clipper 스킬에 넘긴다.
- **고르기 전에는 아무것도 하지 않는다.** 현황을 보여주고 사용자가 고른 것만 한다.
- **제외는 지우는 게 아니다.** clip-log에 "제외" 한 줄을 더할 뿐이고, 이전 기록은 그대로 남는다. 나중에 다시 클리핑해 성공하면 자연스럽게 되살아난다.

## 스크립트

`${CLAUDE_SKILL_DIR}/scripts/failures.py`를 실행한다(이하 `failures`). 결과는 JSON 한 줄이다.

| 명령 | 하는 일 |
|---|---|
| `failures status --root ROOT [--include-excluded]` | 링크별 마지막 상태로 실패 현황을 분류 |
| `failures exclude --root ROOT --url URL [--url ...]` | 재시도 대상에서 제외 |

## 진행 순서

### 1. 클립 위치 정하기

위에서부터 처음 해당하는 것을 클립 위치(이하 ROOT)로 쓴다: 이번 요청에서 말한 위치, 프로젝트 CLAUDE.md의 클립 저장 위치 규칙, `clips/`. ROOT나 그 안의 clip-log.md가 없으면 "기록된 실패가 없어요"라고 알리고 끝낸다.

### 2. 현황 보여주기

`failures status --root ROOT`를 실행한다. 사용자가 "제외한 것도"라고 했으면 `--include-excluded`를 붙인다. 실패가 없으면 그렇게 알리고 끝낸다.

분류별 개수를 먼저 보여주고, 그 아래에 링크를 번호와 함께 나열한다.

```
재시도 가능 3개: 네트워크: 시간 초과 2, 접근 제한: 봇 차단: 확인 시간 초과 1
재시도 불가 2개: 접근 제한: 로그인 필요 1, 페이지 없음: 404 1

1. https://... (네트워크: 시간 초과, 2026-10-15)
...
```

### 3. 무엇을 할지 묻기

진행을 정하는 질문이므로 선택지를 보여준다.

- 재시도 가능한 N개 모두 다시 시도
- 골라서 다시 시도 (번호로)
- 재시도 대상에서 제외 (번호로)
- 그대로 두기

재시도 불가 링크도 사용자가 원하면 다시 시도할 수 있다. 다만 결과가 같을 가능성이 높다고 알린다.

### 4. 고른 일 하기

- **다시 시도:** 고른 링크를 link-clipper 스킬로 클리핑한다. 기록, 결과 알림, 요약 질문은 link-clipper가 한다.
- **제외:** `failures exclude --root ROOT --url ...`로 제외하고, 제외한 링크 수를 알린다.

### 5. 실패 유형별 안내

다시 시도한 뒤에도 남은 실패나 재시도 불가 링크에는 유형에 맞게 한 줄씩 안내한다.

| 유형 | 안내 |
|---|---|
| 봇 차단: 확인 시간 초과 | 다시 시도할 때 Chrome 창이 뜨면 확인 버튼을 직접 눌러 주세요 |
| 접근 제한 (로그인 필요, 권한 없음, 봇 차단) | 브라우저에서 페이지를 저장(⌘+S)해 `inbox/`에 넣으면 클리핑할 수 있어요 |
| 페이지 없음 | 사라진 페이지라 제외하는 걸 권해요 |
| 네트워크, 서버 오류 | 잠시 뒤 다시 시도해 보세요 |
