# 저장소 PR 템플릿

## 언제 읽는가

저장소에 PR 템플릿이 있을 때 읽는다. 보고서 코멘트는 템플릿과 상관없이 SKILL.md 규칙 그대로 쓴다. 이 문서는 본문만 다룬다.

## 템플릿 찾기

GitHub이 인식하는 아래 위치를 대소문자 구분 없이 찾는다.

- 하나짜리: `.github/pull_request_template.md`, `pull_request_template.md`(저장소 루트), `docs/pull_request_template.md`
- 여러 개: `.github/PULL_REQUEST_TEMPLATE/`, `PULL_REQUEST_TEMPLATE/`, `docs/PULL_REQUEST_TEMPLATE/` 아래의 `.md` 파일

CLAUDE.md, CONTRIBUTING.md 같은 저장소 지침에 PR 규칙이 있으면 함께 따른다. 템플릿이나 지침이 이 스킬의 규칙과 다르면 저장소 쪽을 따른다.

## 섹션 채우기

- 템플릿의 섹션 제목, 순서, 고정 문구, 안내용 HTML 주석(`<!-- … -->`)은 바꾸지 않는다.
- 각 섹션에는 그 섹션이 요구하는 내용을 쓴다. 저장소 지침이 언어를 정하지 않았으면 내용은 한국어 개조식으로 쓴다.
- Summary와 Changes는 같은 역할의 템플릿 섹션에 넣는다. 예: "변경 사항", "What", "Description"
- 같은 역할의 섹션이 없으면 템플릿 섹션들 뒤에 SKILL.md의 `## Summary`, `## Changes`를 덧붙인다. 템플릿이나 지침이 섹션 추가를 금지하면 덧붙이지 않는다.
- 근거가 없어 채울 수 없는 섹션(예: 스크린샷)은 비워 두고, 보고서 코멘트의 Please check에 "<섹션 이름> 작성 필요"를 적는다.

## 체크리스트

- 실제로 확인한 항목만 체크한다. 예: 테스트 파일을 추가했으면 "테스트 추가"를 체크한다.
- 확인하지 못한 항목은 체크하지 않고, 보고서 코멘트의 Please check에 "<항목> 확인 필요"를 적는다.

## 템플릿이 여러 개일 때

- 파일 이름이 브랜치 type과 맞으면 그것을 쓴다. 예: `fix` → `bug_fix.md`, `bugfix.md`
- 맞는 것이 없으면 이름순 첫 번째 파일을 쓴다.
- 확인 모드는 마지막 확인 화면의 "PR 템플릿" 줄에 고른 파일과 다른 후보를 보여준다. 사용자가 다른 템플릿을 고르면 다시 써서 같은 질문을 한다. 자동 모드는 마무리 안내에 고른 파일을 알린다.
