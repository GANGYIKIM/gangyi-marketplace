# 결정 대기 PR

## 언제 읽는가

아래 중 하나에 해당할 때 읽는다.

- `refs/git-kit/decisions/<현재 브랜치>` 기록이 있을 때
- 기존 PR의 제목이 🚧로 시작할 때. 다른 컴퓨터에서 만든 결정 대기 PR이라 로컬 기록이 없는 경우다.

기록 내용은 `git cat-file -p refs/git-kit/decisions/<현재 브랜치>`로 읽는다.

## 제목과 Draft

- 제목의 이모지 자리를 🚧로 둔다. type과 description은 SKILL.md 규칙 그대로다. 예: `🚧 feat: add account lockout after failed logins`
- 모드와 상관없이 Draft로 만든다.
- **base**: 기록의 "따온 브랜치"를 본다.
  - 따온 브랜치가 기본 브랜치이거나 이미 머지됐으면 → base는 기본 브랜치
  - 따온 브랜치에 열린 PR이 있으면 → base는 따온 브랜치. 결정 부분에 `머지 순서` 줄을 쓴다.
  - 따온 브랜치가 원격에 없거나 PR이 없으면 → PR을 만들지 않는다. SKILL.md의 "PR을 만들지 않을 때" 템플릿에 이유 `따온 브랜치 PR 없음`으로 알리고 끝낸다.

## 보고서 코멘트

결정 부분은 `${CLAUDE_PLUGIN_ROOT}/shared/report.md`의 "결정 부분 템플릿"으로 쓴다. 표시, 섹션별 담당, 머지 순서, 표시가 깨졌을 때와 예전 보고서도 그 파일을 따른다. 결정 부분 뒤의 Decisions made와 Please check는 SKILL.md의 "3. 보고서 코멘트" 규칙을 따르고, 있을 때만 쓴다.

- **처음에만 만든다**: 결정 부분은 보고서를 처음 만들 때만 기록으로 만든다. 기존 보고서가 있으면 결정 표시 안쪽을 한 글자도 바꾸지 않고 그대로 옮긴다. 그 뒤에 고치는 것은 decision-resolver의 일이다.
- **D 블록**: 기록의 번호와 상태 그대로 쓴다. `- 결정:` 줄은 report.md 규칙대로 기록의 상태에 맞춰 쓴다. 예전 형식 기록은 D1 하나로 읽는다.
- **내용의 출처**: 결정할 것, 미결정 이유, 선택지와 추천, 의존은 ref 기록에서 가져온다. 현재 임시값과 관련 위치는 지금 코드에서 찾는다.
- **현재 임시값**: 임시로 넣은 값이나 동작이 있을 때만 쓴다.
- **의존**: 기록에 `의존:` 줄이 있는 D에만 그대로 옮긴다. 스스로 판단해 더하거나 고치지 않는다.
- **관련 위치**: 결정이 나면 고쳐야 할 곳을 빠짐없이 모두 쓴다. 개수를 줄이지 않는다. 위치가 1곳이어도 이 목록 형식으로 쓴다. 위치 형식은 SKILL.md의 "위치 표기"를 따른다.
- **선택지**: 2~4개를 쓴다. 추천은 정확히 하나에만 "(추천)"을 붙이고 맨 위에 둔다.
- **기록에 선택지가 없을 때**: 예전 형식의 기록이거나 사람이 직접 만든 브랜치처럼 선택지가 없으면, 대화 맥락에 있을 때만 그것을 쓴다. 맥락에도 없으면 선택지를 지어내지 않는다. 체크박스 없이 질문, 미결정 이유, 관련 위치만 쓰고 "선택지는 PR 코멘트로 답"이라고 적는다.
