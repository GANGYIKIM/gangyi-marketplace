# 결정 대기 PR

## 언제 읽는가

아래 중 하나에 해당할 때 읽는다.

- `refs/git-kit/decisions/<현재 브랜치>` 기록이 있을 때
- 기존 PR의 제목이 🚧로 시작할 때. 다른 컴퓨터에서 만든 결정 대기 PR이라 로컬 기록이 없는 경우다.

기록 내용은 `git cat-file -p refs/git-kit/decisions/<현재 브랜치>`로 읽는다.

## 제목과 Draft

- 제목의 이모지 자리를 🚧로 둔다. type과 description은 SKILL.md 규칙 그대로다. 예: `🚧 feat: add account lockout after failed logins`
- 모드와 상관없이 Draft로 만든다.
- **base**: 기록의 "따온 브랜치"를 본다.
  - 따온 브랜치가 기본 브랜치이거나 이미 머지됐으면 → base는 기본 브랜치
  - 따온 브랜치에 열린 PR이 있으면 → base는 따온 브랜치. WARNING 마지막 줄에 그 PR 번호를 쓴다.
  - 따온 브랜치가 원격에 없거나 PR이 없으면 → PR을 만들지 않고 "따온 브랜치의 PR을 먼저 만들어야 함"을 알리고 끝낸다.

## 보고서 코멘트

```
<!-- git-kit:report -->
> [!WARNING]
> 결정 대기. 머지 전 아래 Decisions needed의 결정 필요.
> 답하는 법: 항목마다 선택지 하나 체크. 선택지에 없는 답은 PR 코멘트로 작성. 이후 Claude에게 결정 반영 요청.
> #<따온 브랜치 PR 번호> 먼저 머지 필요.

## Decisions needed
### D<번호>. <결정할 것>
- 미결정 이유: <이유, 개조식>
- 현재 임시값: <임시값>
- 의존: D<번호>가 <선택지>일 때만 필요
- 관련 위치:
  - [`<경로>:<줄>`](<고정 링크>) <역할>
- [ ] <선택지> (추천): <장단점, 개조식>
- [ ] <선택지>: <장단점, 개조식>

## Decisions made
- 가장 어려운 결정: <정한 것과 이유, 개조식> <위치>
- 버린 대안: <버린 것과 이유, 개조식> <위치>

## Please check
- [ ] <사람이 확인할 것, 개조식> <위치>
- [x] <확인을 마친 것, 개조식> <위치>
  - 확인 결과: [<결과>](<결과 코멘트 링크>)
```

- WARNING의 마지막 줄은 base가 따온 브랜치일 때만 쓴다.
- D 번호는 1부터 매긴다.
- **내용의 출처**: 결정할 것, 미결정 이유, 선택지와 추천은 ref 기록에서 가져온다. 현재 임시값과 관련 위치는 지금 코드에서 찾는다.
- **현재 임시값**: 임시로 넣은 값이나 동작이 있을 때만 쓴다.
- **의존**: 다른 결정의 답에 따라 필요 없어지는 항목에만 쓴다.
- **관련 위치**: 결정이 나면 고쳐야 할 곳을 빠짐없이 모두 쓴다. 개수를 줄이지 않는다. 위치가 1곳이어도 이 목록 형식으로 쓴다. 위치 형식은 SKILL.md의 "위치 표기"를 따른다.
- **선택지**: 2~4개를 쓴다. 추천은 정확히 하나에만 "(추천)"을 붙이고 맨 위에 둔다.
- **기록에 선택지가 없을 때**: 예전 형식의 기록이거나 사람이 직접 만든 브랜치처럼 선택지가 없으면, 대화 맥락에 있을 때만 그것을 쓴다. 맥락에도 없으면 선택지를 지어내지 않는다. 체크박스 없이 질문, 미결정 이유, 관련 위치만 쓰고 "선택지는 PR 코멘트로 답"이라고 적는다.
- Decisions made와 Please check는 SKILL.md의 "3. 보고서 코멘트" 규칙을 따르고, 있을 때만 쓴다.
