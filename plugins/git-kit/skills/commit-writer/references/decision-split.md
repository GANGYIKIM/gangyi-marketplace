# 결정 대기 변경 분리 절차

결정이 필요한 변경이 끝난 작업을 막지 않도록 따로 떼어내는 절차다. 결정을 어떻게 구현할지는 정하지 않는다. git으로 나누고 기록하는 일만 한다.

## 언제 읽는가

커밋할 변경 중에 사람의 결정이 있어야 완성되는 변경(이하 결정 대기 변경)이 섞여 있을 때 읽는다.

- 사용자가 "이건 아직 결정 안 됐어"처럼 알려준 경우
- 작업 중인 AI가 사람의 답이 필요한 지점을 만났다고 판단한 경우

결정이 필요 없는 일반 변경만 있으면 읽지 않는다.

## 절차

1. **나누기**: 변경 파일을 "결정 대기"와 "그 외"로 나눈다. 파일 단위로만 나눈다. 한 파일에 둘이 섞여 있으면 결정 대기 쪽에 넣고 "섞인 파일"로 알린다. 결정이 안 된 코드가 커밋되는 것보다 일부 완료된 코드가 늦게 커밋되는 쪽이 안전하기 때문이다.
2. **결정할 것 정리**: 대화 맥락(사용자가 말한 미결 사항, AI가 만난 질문)에서 결정마다 아래를 정리한다. 이 맥락은 세션이 끝나면 사라지므로, 지금 정리해서 7번 단계의 기록에 남긴다.
   - 결정할 것: 한 문장
   - 미결정 이유: AI가 정하지 않은 이유, 개조식
   - 선택지: 2~4개와 각각의 장단점, 개조식. 추천은 정확히 하나에만 "(추천)"을 붙이고 맨 위에 둔다.
   - 결정 의존: 한 결정의 특정 선택지를 고르면 다른 결정의 코드가 필요 없어지고, 그 사실이 대화에 있을 때만 정리한다. 어느 결정의 어느 선택지인지와 그 근거를 함께 정리한다.
3. **확인**: 확인 모드는 SKILL.md의 분할안에 아래 "결정 대기 묶음"을 넣어 한 번에 확인받는다. 자동 모드는 바로 진행한다.
   ```
   결정 대기 · <새 브랜치>로 옮김
   - 결정할 것: <결정할 것>
   - 옮길 파일: <파일>
   - 따올 브랜치: <따올 브랜치> (<따올 이유>)
   ```
   - 결정할 것이 여럿이면 "결정할 것" 줄을 `- 결정할 것: D1 <결정할 것>, D2 <결정할 것>`처럼 한 줄에 쓴다. 번호는 7번 단계의 번호와 같다.
   - "그 외" 변경이 없을 때는 첫 줄을 `결정 대기 · <현재 브랜치>에 그대로 둠`으로 쓰고 "따올 브랜치" 줄을 뺀다.
4. **"그 외"가 없을 때**: 결정 대기 변경만 있으면 새 브랜치를 따로 만들지 않는다. 빈 원래 브랜치가 남지 않게 하기 위해서다.
   - 지금 브랜치가 보호 브랜치가 아니면 지금 브랜치를 결정 대기 브랜치로 쓴다. 5·6번 단계를 건너뛰고 7번(기록)부터 한다.
   - 보호 브랜치면 SKILL.md의 "브랜치 확인" 규칙대로 새 브랜치를 만들고, 그 브랜치를 결정 대기 브랜치로 쓴다.
   - 기록의 "따온 브랜치"는 지금 브랜치가 갈라져 나온 브랜치다. 알 수 없으면 기본 브랜치를 쓴다.
   - 안내는 아래 "결정 대기 변경만 있을 때" 템플릿을 쓴다.
5. **그 외 커밋**: "그 외" 변경을 SKILL.md의 "2. 변경 분할"부터 "4. 확인과 커밋"까지의 규칙대로 지금 브랜치에 커밋한다.
6. **새 브랜치 만들기**: 결정 대기 변경을 들고 새 브랜치를 만든다. 이름은 SKILL.md의 "브랜치 이름" 규칙을 따른다.
   - 결정 대기 변경이 방금 커밋한 작업에 의존하면 → 지금 브랜치에서 딴다. `git switch -c <이름>`
   - 의존하지 않으면 → 로컬 기본 브랜치에서 딴다. `git switch -c <이름> <기본 브랜치>`
   - 의존하는지 애매하면 지금 브랜치에서 딴다. 그 위에서 따면 항상 동작하기 때문이다.
   - 기본 브랜치에서 따다가 커밋 안 된 변경과 부딪혀 git이 거부하면, 지금 브랜치에서 따고 그 사실을 알린다.
7. **결정 대기 기록**: `${CLAUDE_PLUGIN_ROOT}/shared/decision-record.md`를 읽고, 그 형식과 쓰는 법대로 결정 대기 브랜치의 기록을 쓴다.
   - **새로 쓸지 더할지**:
     - 이번 실행에서 결정 대기 브랜치를 새로 만들었으면 → 기록을 새로 쓴다. 같은 이름의 기록이 있으면 덮어쓴다.
     - 이미 있던 브랜치(4번 단계의 지금 브랜치)이고 기록이 있으면 → 기존 기록 끝에 D 블록을 더한다. 번호는 기존 마지막 번호 다음부터 매긴다.
     - 이미 있던 브랜치이고 기록이 없으면 → 새로 쓴다.
   - **D 블록**: 2번 단계에서 정리한 결정마다 하나씩 쓴다. 상태는 `대기`로 쓰고, 답에 관한 줄(고른 답, 답한 곳, 결정한 날, 결정 시점, 반영 커밋, 이전 답)은 쓰지 않는다.
   - **번호 순서**: 다른 결정이 의존하는 결정을 먼저 둔다. 의존이 없으면 대화에서 나온 순서대로 둔다.
   - **결정 의존**: 아래 두 조건을 모두 만족할 때만 `의존:` 줄을 쓴다. 아니면 쓰지 않는다.
     - 한 결정의 특정 선택지를 고르면 다른 결정의 코드가 필요 없어진다.
     - 그 사실이 대화에 있다(사람이 말했거나, AI가 정리한 선택지의 장단점에 적혀 있다).
     - 형식과 제한(더 작은 번호만, 조건 하나)은 공통 파일의 "결정 의존"을 따른다. 조건이 둘 이상이면 쓰지 않고 미결정 이유에 글로 적는다.
   - **예전 형식**: 기존 기록이 예전 형식이면 D 블록을 더할 때 공통 파일의 "예전 형식"대로 새 형식으로 바꿔 함께 쓴다.
   - **확인**: 쓴 뒤 `git cat-file -p`로 다시 읽어, 쓰려던 줄과 같은지 비교한다. 다르거나 명령이 실패하면 기록 실패다. 실패해도 커밋과 분리는 그대로 진행하고, 마무리 안내에 "기록 실패 줄"을 더한다. 성공하면 안내에 쓰지 않는다.
   - **지우지 않는다**: commit-writer는 기록을 지우지 않는다. 결정 대기 브랜치에서 커밋을 이어서 해도, 커밋만으로는 결정이 났는지 알 수 없기 때문이다.
8. **모드별 처리**
   - 확인 모드: 결정 대기 변경을 커밋하지 않는다. 결정 대기 브랜치에 옮겨만 둔다.
   - 자동 모드: 결정 대기 브랜치에서 지금 상태 그대로 커밋한다. 다른 브랜치로 옮겨 다닐 때 변경이 따라오지 않게 하기 위해서다. 메시지는 SKILL.md의 "3. 메시지 작성" 규칙을 따르고, "wip", "draft" 같은 표시 대신 지금 코드가 하는 일을 쓴다. 결정 대기 상태는 PR 제목과 본문이 보여준다.

## 분리 후 안내

SKILL.md의 "5. 마무리 안내" 대신 아래 템플릿을 쓴다. 템플릿 규칙은 SKILL.md의 "안내 언어와 형식"을 따른다. 섞인 파일, 제외됨 같은 SKILL.md 정상 종료 템플릿의 나머지 줄은 해당할 때 맨 아래에 그대로 붙인다.

- 커밋 줄은 커밋마다 하나씩 쓴다.
- "임시 구현"은 결정 대기 변경에 임시로 넣은 값이나 동작이 있을 때만 쓴다. 코드를 고치거나 판단하지 않고, 보이는 그대로 한 줄로 쓴다.
- "기록 실패"는 7번 단계의 기록에 실패했을 때만 맨 아래에 붙인다. 기록에 성공한 사실은 쓰지 않는다.

### 확인 모드

```
커밋 완료 (<커밋 수>개, 브랜치 2개)

<원래 브랜치>
- <해시 7자리> <커밋 메시지>

<새 브랜치> · 결정 대기  ← 현 위치
- 결정할 것: <결정할 것>
- 따온 브랜치: <따온 브랜치> (<따온 이유>)
- 옮긴 파일: <파일>
- 임시 구현: <임시로 넣은 값이나 동작> (<파일>:<줄>)
- 다음: 결정 반영 후 이 브랜치에서 이어서 커밋
- 다음: 원래 작업으로 돌아가려면 옮긴 파일을 커밋하거나 stash한 뒤 `git switch <원래 브랜치>` (그냥 이동하면 옮긴 파일이 따라감)
```

### 자동 모드

```
커밋 완료 (<커밋 수>개, 브랜치 2개)

<원래 브랜치>
- <해시 7자리> <커밋 메시지>

<새 브랜치> · 결정 대기  ← 현 위치
- <해시 7자리> <커밋 메시지>
- 결정할 것: <결정할 것>
- 따온 브랜치: <따온 브랜치> (<따온 이유>)
- 임시 구현: <임시로 넣은 값이나 동작> (<파일>:<줄>)
- 다음: 결정 반영 후 이 브랜치에서 이어서 커밋
```

### 결정 대기 변경만 있을 때

자동 모드는 결정 대기 변경을 지금 브랜치에 커밋하고 아래로 알린다.

```
커밋 완료 (<커밋 수>개) · <현재 브랜치>

- <해시 7자리> <커밋 메시지>

새 브랜치: <브랜치> (<보호 브랜치>에서 생성)
결정 대기: <결정할 것>
임시 구현: <임시로 넣은 값이나 동작> (<파일>:<줄>)
다음: 결정 반영 후 이 브랜치에서 이어서 커밋
```

확인 모드는 결정 대기 변경을 커밋하지 않고 기록만 남긴 뒤 아래로 알린다.

```
커밋하지 않음 · 결정 대기 변경만 있음
현재 브랜치: <현재 브랜치>
결정 대기: <결정할 것>
임시 구현: <임시로 넣은 값이나 동작> (<파일>:<줄>)
다음: 결정 반영 후 다시 커밋 요청
```

- "새 브랜치"는 보호 브랜치에서 새 브랜치를 만들었을 때만 쓴다.

### 기록 실패 줄

```
기록 실패: <이유> (pr-writer와 branch-cleaner가 이 브랜치를 결정 대기로 알아보지 못할 수 있음)
```
