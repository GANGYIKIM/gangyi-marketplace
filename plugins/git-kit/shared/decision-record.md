# 결정 기록

결정 대기 브랜치의 결정을 git ref에 남기는 형식이다.
commit-writer, pr-writer, decision-resolver가 읽는다.

## 스킬별 역할

| 스킬 | 하는 일 |
|---|---|
| commit-writer | 새로 쓴다. D 블록과 결정 의존을 쓴다. 상태는 대기. |
| pr-writer | 읽어서 PR 보고서로 옮긴다. 기록은 바꾸지 않는다. |
| decision-resolver | 답과 상태를 쓴다. 보고서로 기록을 다시 만든다. 모두 끝나면 지운다. |

## 위치와 다루는 법

- 위치: `refs/git-kit/decisions/<브랜치 이름>`
- git 명령으로만 다룬다. `.git`은 보호 경로라 파일을 직접 쓰면 막힌다.
- 원격에 올라가지 않는다. worktree끼리는 공유된다.
- 읽기: `git cat-file -p refs/git-kit/decisions/<브랜치>`
- 쓰기: 기록 전체를 한 번에 다시 쓴다. 한 줄씩 인자로 넘긴다.
  ```bash
  printf '%s\n' '<줄>' '<줄>' … \
    | git hash-object -w --stdin \
    | xargs git update-ref refs/git-kit/decisions/<브랜치>
  ```
- 쓴 뒤 다시 읽어 확인한다.
- 지우기: `git update-ref -d refs/git-kit/decisions/<브랜치>`

## 기록이 이미 있을 때 (commit-writer)

- 브랜치를 새로 만들었는데 기록이 있으면 덮어쓴다. 같은 이름의 브랜치가 지워진 뒤 남은 오래된 기록이기 때문이다.
- 이미 있던 결정 대기 브랜치에 결정이 또 생기면 다음 번호로 D 블록을 더한다. 머리와 기존 D 블록은 그대로 둔다.

## 형식

```
따온 브랜치: feat/login
기록한 날: 2026-10-21

D1. 로그인 실패 시 계정을 잠글지
상태: 반영됨

미결정 이유: 기획 문서에 기준 없음. 보안과 사용성 사이 제품 판단 필요.
선택지:
- 잠금 (추천): 무차별 대입 방어. 오타 잦은 사용자는 불편.
- 잠그지 않음: 사용성 좋음. 방어는 지연 시간에 의존.

고른 답: 잠금
답한 곳: PR 체크박스
결정한 날: 2026-10-27
결정 시점: a1b2c3d
반영 커밋: e4f5a6b

D2. 몇 회 실패에 잠글지
상태: 대기
의존: D1이 잠금일 때만 필요

미결정 이유: 보안 정책 기준 없음.
선택지:
- 5회 (추천): 일반적인 기준.
- 10회: 관대함. 방어력 낮음.
```

- 머리: 따온 브랜치, 기록한 날
- D 블록은 빈 줄로 나눈 3덩어리다.
  - 머리 덩어리: `D<번호>. <결정할 것>`, `상태:`, `의존:` (의존은 있을 때만)
  - 문제 덩어리: `미결정 이유:` (AI가 정하지 않고 사람에게 넘긴 이유), `선택지:`
  - 답 덩어리: 결정됐을 때만 쓴다
    - `고른 답:`
    - `답한 곳:` (체크박스, 대화, 대화(추천 따름), PR 코멘트 @사람)
    - `결정한 날:`
    - `결정 시점:` (그때 `origin/<브랜치>` 커밋, 7자리)
    - `반영 커밋:` (반영됨일 때만, 여러 개면 쉼표)
    - `이전 답:` (답이 바뀌었을 때만, `<답> (<날짜>)`)
- 블록은 `D<번호>.` 줄로 알아본다. 번호는 1부터 차례로 붙이고, 다시 쓰지 않는다.
- 추천은 정확히 하나에만 붙이고, 맨 위에 둔다.
- 관련 위치는 적지 않는다. 코드에서 다시 찾는다.

## 상태

| 상태 | 뜻 | 바꾸는 스킬 |
|---|---|---|
| 대기 | 답 없음 | commit-writer가 처음 씀 |
| 결정됨 | 답 있음, 아직 반영 안 됨 | decision-resolver |
| 반영됨 | 반영 커밋 있음 | decision-resolver |
| 필요 없음 | 결정 의존 조건이 안 맞음 | decision-resolver |

## 결정 의존

- 다른 결정의 답에 따라 이 결정이 필요 없어질 수 있을 때만 쓴다.
- 형식: `의존: D<번호>가 <선택지>일 때만 필요` (조건 하나, 선택지 이름 그대로)
- 더 작은 번호의 D만 가리킨다.
- 판단: 번호 순서대로 한 번 한다.
  - 조건 맞음 → 필요
  - 안 맞음 → 필요 없음
  - 대상이 대기 → 대기
  - 대상이 자유 답 → 대기 + 사람 확인 필요
- 의존 오류: 같거나 큰 번호, 없는 D, 선택지에 없는 값, 조건 둘 이상, 형식 불일치. 이때는 그 D와 그것에 의존하는 D만 멈추고 알린다.
- 지원하지 않음
  - 조건 둘 이상: 결정 하나로 합친다.
  - 다른 브랜치의 결정에 의존: 미결정 이유에 글로 적는다.

## 답이 바뀔 때

- 결정됨: 고른 답, 결정한 날, 결정 시점을 새로 쓴다.
- 반영됨: 결정됨으로 되돌린다. 반영 커밋을 지우고 `이전 답:`을 쓴다.
- 결정 대기가 끝난 뒤: 다루지 않는다. 일반 변경이다.
- 바뀐 뒤 결정 의존을 다시 판단한다.

## 예전 형식

- `D<번호>.` 줄이 없으면 예전 형식이다. 전체를 D1 하나, 상태 대기로 읽는다.
- `결정할 것:` 줄이 D1의 제목이 된다.
- 다음에 쓸 때 새 형식으로 바꾼다.
- 읽을 수 없는 기록은 고치지 않고 알린다.
