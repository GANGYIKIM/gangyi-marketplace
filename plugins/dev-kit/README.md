# dev-kit

AI와 개발할 때 지킬 것을 문서가 아니라 검사(훅, 권한, 린트)로 지키게 하는 개발 스킬 모음입니다. Claude Code의 훅과 권한 설정을 쓰므로 Claude Code에서 동작합니다.

## 스킬

| 스킬 | 설명 | 호출 |
|---|---|---|
| harness-builder | 프로젝트가 개발을 시작하기 전에 갖춰야 할 조건(포맷, 정적 검사, 타입 검사, 테스트 도구, 커밋 전 검사, 화면과 로직의 분리, AI가 검사를 피하지 못하게 하는 훅과 권한)을 점검하고, 빠진 것을 설치한 뒤 위반 예시로 실제로 막히는지 확인합니다. 빈 폴더에서는 앱 뼈대부터 만듭니다 | `/dev-kit:harness-builder` 또는 "셋업해줘" |

## 설치

```
/plugin install dev-kit --marketplace GANGYIKIM/gangyi-marketplace
```

git과 Node.js가 필요합니다. AI가 검사를 건너뛰지 못하게 막는 훅 스크립트가 Node.js로 돕니다.

## 사용할 때 알아 둘 것

- 셋업은 쓸 도구를 묻고, 더하거나 바꿀 것을 목록으로 보여 준 뒤, 진행을 고르면 설치하고 확인합니다. 진행을 고르기 전에는 아무것도 바꾸지 않습니다. 커밋은 하지 않습니다.
- 프로젝트가 이미 쓰는 도구는 바꾸지 않고, 없는 것만 더합니다. 이미 있는 설정이 조건과 다르면 덮어쓰지 않고 보여 주고 고르게 합니다.
- 실제로 설치해 확인한 스택은 Next.js, Vite + React, 프레임워크 없는 TypeScript 프로젝트입니다. 도구는 프로젝트가 이미 쓰는 것, 뼈대가 주는 것, 추천 도구 순으로 정합니다. 그 밖의 스택과 도구는 공식 문서를 찾아 같은 조건으로 진행합니다.
- 셋업한 프로젝트에는 `.claude/settings.json`의 훅과 권한 규칙, `.claude/hooks/block-hook-bypass.mjs`가 남습니다. 그 뒤로 AI가 검사를 건너뛰는 커밋(`git commit --no-verify` 등)을 하면 막히고, 파일 수정 도구로 검사 설정 파일을 고치려 하면 확인 창이 뜹니다. 셸 명령으로 고치는 것에는 창이 뜨지 않습니다.
- dev-kit을 켜 두면 파일 쓰기의 확인 창이 뜰 때마다 작은 스크립트가 돕니다. 쓰려는 내용이 지금 파일과 같으면 창을 띄우지 않고 거절합니다. 셋업이 권한 규칙이 동작하는지 사람에게 묻지 않고 확인하는 데 씁니다.
- 앱을 하위 폴더에 만들면 그 폴더에서 Claude Code를 다시 열고 셋업을 한 번 더 요청해 주세요. Claude Code는 연 폴더의 설정만 읽으므로, 다시 열어야 훅과 권한 규칙이 실제로 막는지 확인할 수 있습니다.
- 패키지 매니저처럼 컴퓨터 전체에 쓰이는 도구는 설치하지 않습니다. 없으면 설치 명령을 알려 주고 멈춥니다.

## 테스트

스킬을 쓰는 데는 필요 없습니다. 이 플러그인을 고쳤을 때, PR을 올리기 전에 돌립니다. 무엇을 돌릴지는 고친 것에 따라 다릅니다.

| 고친 것 | 돌릴 것 |
|---|---|
| 훅 스크립트 (`skills/harness-builder/assets/`, `hooks/`) | 훅 스크립트 테스트 |
| 스킬 문서 (`SKILL.md`, `references/`) | 평가 |
| 설치와 확인 단계의 규칙, 스택 파일이 정한 도구 | 평가를 돌린 뒤 실제 프로젝트에 써 보기 |

플러그인 폴더에서 실행합니다.

```bash
node --test "tests/*.test.mjs"                                                   # 훅 스크립트 테스트
claude plugin eval . --scaffold --allow-tools Bash Write Edit --ablation none   # 평가 (사용량 차감)
```

- 훅 스크립트 테스트는 AI를 부르지 않아 바로 끝납니다. 어떤 명령을 막고 어떤 명령을 통과시키는지, 어떤 쓰기를 거절하는지 봅니다.
- 평가는 `evals/`에 있는 [claude plugin eval](https://code.claude.com/docs/en/plugin-evals) 형식의 케이스입니다. 스킬이 정해진 질문과 화면을 그대로 내는지, 진행을 고르기 전에 아무것도 바꾸지 않는지 봅니다.
  - `--scaffold`: 케이스마다 시험할 프로젝트를 미리 만드는 데 필요합니다.
  - `--allow-tools Bash Write Edit`: 스킬이 프로젝트를 살펴보는 데 Bash가 필요합니다. Write와 Edit은 쓸 수 있는데도 쓰지 않는지 보려고 허용합니다.
  - `--ablation none`: 플러그인 없이 한 번 더 돌려 비교하는 실행을 뺍니다.
  - 몇 번 돌릴지는 [.claude/rules/git-kit-testing.md](../../.claude/rules/git-kit-testing.md)의 "몇 번 돌리나"와 같은 기준을 따릅니다.
  - `stops-when-tool-missing` 케이스는 pnpm이 깔려 있지 않은 컴퓨터를 전제로 합니다.
- 평가는 설치 전 단계까지만 봅니다. 평가 환경에 네트워크가 없어 설치와 확인 단계는 돌지 않습니다. 그 단계를 고쳤으면 빈 폴더나 작은 프로젝트에 실제로 셋업해 보고, 확인한 것과 결과를 그 변경의 PR Testing에 씁니다.
