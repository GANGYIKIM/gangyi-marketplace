# JS·TS

## 고르기의 선택지

| 항목 | 추천값 (이유) | 대안 |
|---|---|---|
| 패키지 매니저 | npm (Node와 함께 깔려 있어 따로 준비할 것이 없음) | 이 컴퓨터에 깔린 pnpm, yarn, bun |
| 테스트 도구 | Vitest (설정이 적고 TypeScript를 바로 읽음) | Jest |
| 스타일 | Tailwind CSS (토큰을 CSS 한 곳에 두고 클래스에 검사를 걸 수 있음) | CSS Modules |
| 컴포넌트 자리와 데이터 자리 | `components/`와 `data/` (프로젝트에 `src/`가 있거나 뼈대가 `src/`를 만들면 그 안) | 사람이 말한 폴더 이름 |
| 미리 볼 자리 | 미리 보기 페이지 (설치할 것이 없고 주소만 열면 찍을 수 있음) | Storybook |

## 뼈대

프레임워크가 "없음"이면 `package.json`과 TypeScript 설정을 만든다.

## 조건

### Project

| 조건 | 추천 도구 |
|---|---|
| 코드 모양 통일 | Prettier |
| 정적 검사 | ESLint |
| 타입 검사 엄격 | TypeScript의 엄격 모드 |
| 명령 이름 | `package.json`의 스크립트 |
| 커밋 전 검사 | husky + lint-staged |

조건마다 꼭 지켜야 하는 것:

- **정적 검사**: 필수 조건의 규칙은 error 수준으로, 권고의 규칙은 warn 수준으로 둔다. 경고가 커밋을 막아서는 안 된다.
- **타입 검사 엄격**: 타입 검사가 프로젝트 설정대로 앱 코드를 실제로 검사해야 한다. 설정이 여러 파일로 나뉘어 있어도 같다.
- **명령 이름**: `lint`, `typecheck`, `test`, `format` 네 이름이 있어야 한다. 다른 스킬이 이 이름으로 부른다. 내용은 고른 도구에 맞게 쓰고, 이미 있는 이름은 내용을 바꾸지 않는다.
- **커밋 전 검사**
  - 검사 도구를 직접 부른다. `package.json`의 스크립트를 거치지 않는다. 스크립트를 고쳐 검사를 비우는 길을 막기 위해서다.
  - 관련 테스트가 없는 커밋은 통과해야 한다.

### UI

| 조건 | 추천 도구 |
|---|---|
| 컴포넌트의 서버 호출·저장 금지 | 린터의 제한 규칙 (`no-restricted-*`) |
| 컴포넌트와 데이터의 분리 | dependency-cruiser |
| 접근성 (JSX를 쓰지 않을 때) | html-eslint |
| 화면 찍기 | Playwright의 CLI |

조건마다 꼭 지켜야 하는 것:

- **컴포넌트의 서버 호출·저장 금지**: 막을 것은 세 가지다.
  - 서버 호출 (`fetch` 같은 네트워크 전역)
  - 브라우저 저장소 (`localStorage`, 쿠키 등)
  - 프로젝트가 쓰는 HTTP·DB·데이터 가져오기 라이브러리의 import
- **접근성 (JSX를 쓰지 않을 때)**
  - 컴포넌트는 린터가 마크업으로 읽는 한 가지 방식(예: `html` 태그를 붙인 템플릿)으로만 마크업을 만든다.
  - 그 밖의 방식으로 만든 마크업(태그 없는 문자열, `innerHTML` 계열)은 린터의 제한 규칙으로 막는다.
  - html-eslint의 접근성 규칙 전체가 error 수준이어야 한다.
- **미리 볼 자리**: 배포한 앱에서는 열리지 않아야 한다.

### AI

- **검사 건너뛰기 금지**: husky는 환경 변수(`HUSKY=0`)로도 건너뛸 수 있다. 훅 스크립트가 이것도 막으므로, 확인할 때 `HUSKY=0 git commit --dry-run`도 시도한다. 다른 훅 도구의 건너뛰는 방법은 스크립트가 막지 못한다.
- **검사 설정 보호**: `package.json`은 보호할 파일에 넣지 않는다. 커밋 전 검사가 스크립트를 거치지 않기 때문이다.

## 확인 방법

| 조건 | 위반 예시가 꼭 담아야 하는 것 | 나와야 하는 것 |
|---|---|---|
| 타입 검사 엄격 | 엄격 모드에서만 오류인 코드 (예: 타입을 안 적은 매개변수) | 실패. 출력에 타입 오류 |
| 컴포넌트와 데이터의 분리 | 컴포넌트가 데이터 자리의 파일에서 타입만 가져옴. 프로젝트가 경로 별칭을 쓰면 별칭으로 | 실패. 출력에 분리 규칙의 이름 |
| 접근성 (JSX를 쓰지 않을 때) | 접근성 위반 하나와, 린터가 읽지 않는 방식으로 만든 마크업 하나를 따로 | 둘 다 실패. 출력에 각각 접근성 규칙과 제한 규칙의 이름 |
