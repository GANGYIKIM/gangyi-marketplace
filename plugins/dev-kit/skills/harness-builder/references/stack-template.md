# 스택 파일의 틀

스택 파일은 "이 스택이라서 달라지는 것"만 적는다. 조건, 진행 순서, 스택과 상관없는 방법(Claude 설정, git으로 하는 확인)은 SKILL.md에 있다.

## 언제 읽는가

- 새 스택 파일을 쓸 때
- 스택 파일이 없는 스택을 셋업할 때. 아래 틀의 절마다 들어갈 내용을 그 스택의 공식 문서에서 찾아 셋업에 쓴다. 파일로 저장하지는 않는다.

## 세 종류

| 종류 | 담는 것 | 예 |
|---|---|---|
| 언어 파일 (`kind: language`) | 그 언어로 만든 프로젝트면 무엇을 쓰든 같은 것 | `js-ts` |
| 라이브러리 파일 (`kind: library`) | 그 라이브러리를 쓰는 프로젝트면 프레임워크와 상관없이 같은 것 | `react` |
| 프레임워크 파일 (`kind: framework`) | 그 프레임워크라서 더해지거나 달라지는 것. 뼈대를 만드는 방법이 여기 있다 | `next` |

- 파일은 `base`로 자기가 기대는 파일을 가리킨다. 방향은 프레임워크 → 라이브러리 → 언어 한쪽뿐이다. 기대어지는 파일은 자기에게 기대는 파일을 모른다.
- 기대는 파일에 이미 있는 내용은 되풀이하지 않고 다른 점만 적는다.
- 내용을 어느 파일에 둘지는 "이것이 없어도 같은가"로 정한다. 프레임워크가 달라도 같으면 라이브러리 파일에, 라이브러리가 달라도 같으면 언어 파일에 둔다.

## 적는 것과 적지 않는 것

결과는 정확히 적고, 그 결과에 이르는 방법은 적지 않는다.

적는 것:

- 추천 도구와 이유. 추천 도구는 프로젝트가 이미 쓰는 것도, 뼈대가 기본으로 주는 것도 없을 때 쓰는 값이다.
- 조건마다 꼭 지켜야 하는 것. SKILL.md의 조건 뜻만으로는 알 수 없는 결과다.
- 위반 예시가 꼭 담아야 하는 것. 그 점이 빠지면 확인해야 할 것을 확인하지 못하는 경우만 적는다.

적지 않는 것:

- SKILL.md의 조건 뜻과 같은 말
- 스택과 상관없이 같은 것. SKILL.md에 둔다.
- 방법과 도구의 사실: 설정 파일의 문법, 옵션 이름, 설치 명령, 특정 버전에서 달라진 점, 예시 코드. 버전마다 달라지고, 틀리면 확인 단계에서 드러난다. 믿을 만한 출처가 있으면 "사실을 확인하는 곳"으로 가리킨다.
- "하지 않는 일"을 늘어놓는 줄. 하지 않아야 결과가 지켜지는 것만 결과로 적는다.

옵션 이름이 없으면 뜻이 전해지지 않을 때만 괄호 안에 예로 적는다.

## frontmatter

| 필드 | 뜻 | 쓰는 파일 |
|---|---|---|
| `name` | 파일 이름과 같은 이름 | 모두 |
| `kind` | `language`, `library`, `framework` 중 하나 | 모두 |
| `when` | 기존 프로젝트에서 이 스택임을 알아보는 표시 | 모두 |
| `verified` | 확인한 날과 확인한 방법 | 모두 |
| `base` | 이 파일이 기대는 파일의 `name` | 라이브러리 파일, 프레임워크 파일 |
| `for` | SKILL.md "만드는 것"의 선택지 중 이 프레임워크로 만들 수 있는 것 | 프레임워크 파일 |
| `recommended` | `true`면 그 "만드는 것"의 추천값. 같은 `for`의 파일 가운데 하나에만 쓴다 | 추천하는 프레임워크 파일 |
| `reason` | 추천하는 이유 한 줄 | 추천하는 프레임워크 파일 |

## 틀

해당하는 내용이 없는 절은 절째 뺀다.

```markdown
---
name: <이름>
kind: <language | library | framework>
base: <기대는 파일의 name>
when: <기존 프로젝트에서 알아보는 표시>
for: <만드는 것>
recommended: true
reason: <추천하는 이유 한 줄>
verified: <확인한 날> (<확인한 방법>)
---

# <스택 이름>

## 사실을 확인하는 곳

| 확인할 것 | 보는 곳 |
|---|---|
| <버전마다 달라지는 것> | <설치된 패키지 안의 문서, 명령, 공식 문서의 자리> |

## 고르기의 선택지

| 항목 | 추천값 (이유) | 대안 |
|---|---|---|
| <SKILL.md "2. 고르기"의 항목> | <값> (<이유 한 줄>) | <값> |

## 뼈대

<프레임워크 파일: 뼈대 도구와, 뼈대를 만들 때 꼭 지켜야 하는 것. 언어 파일: 프레임워크 없이 시작할 때 만들 것.>

## 조건

### <묶음 이름: Project | UI | AI | Recommended>

| 조건 | 추천 도구 |
|---|---|
| <조건> | <도구> |

조건마다 꼭 지켜야 하는 것:

- **<조건>**: <이 스택에서 이 조건을 채우려면 꼭 지켜야 하는 것>

## 확인 방법

| 조건 | 위반 예시가 꼭 담아야 하는 것 | 나와야 하는 것 |
|---|---|---|
| <조건> | <예시에 꼭 들어가야 하는 점> | <실패나 통과, 출력에 보여야 하는 것> |
```

- "사실을 확인하는 곳"은 SKILL.md의 확인 순서(설치된 것, 공식 문서)만으로 충분하면 뺀다.
- "조건"의 묶음에는 이 스택에서 정할 것이 있는 조건만 적는다. 기대는 파일이 이미 정한 조건은 다른 점만 적고, 추천 도구 표는 뺀다.
- "확인 방법"에는 커밋 전 검사를 돌리는 명령을 적지 않는다. SKILL.md에 있다.
